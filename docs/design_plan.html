MedAxis 设计蓝图 基于 Python Qt · VTK C++ · ITK C++ · OpenCASCADE C++ · CGAL C++ 的医疗影像渲染与分割平台

1. 项目愿景

🩻

全格式影像支持

DICOM 单文件 / 文件夹 / 批量导入、NIfTI (.nii/.nii.gz)、NRRD、MetaImage (.mha/.mhd)、RAW 等标准医学影像格式。

🧠

高性能 MRP 渲染

标准 MPR（轴/冠/矢）、任意斜面 Plane Reslice、Curved Planar Reformation (CPR)，核心算法用 C++ 实现保证实时交互。

🔬

医学图像分割

集成 ITK C++ 原生管线（阈值、区域生长、Level Set、分水岭），自定义 C++ 分割算法可无缝注册。

🤖

AI-Native · MCP 协议

内建 MCP Server，将影像加载、分割、测量等操作抽象为 AI 可调用的 Tools，方便对接大模型 Agent。

📐

几何引擎 (C++)

OpenCASCADE 提供精确 B-Spline/NURBS 曲线用于 CPR 路径；CGAL 负责网格重建与计算几何，pybind11 封装。

🧩

Python/C++ 混合

Python 负责 UI + 编排 + MCP；C++ 负责所有性能敏感计算。pybind11 + VTK/ITK 原生 wrapping 做零拷贝桥接。

2. Python / C++ 分工策略 ⚠️ 关键设计决策

核心原则：Python 做"指挥官"，C++ 做"士兵"。所有重计算（渲染、滤波、分割、几何运算）都必须落在 C++ 侧； Python 侧只负责 UI 交互、事件编排、MCP 协议、插件管理等轻量逻辑。

2.2 各层语言归属

模块语言理由

io/ (文件解析) Python pydicom / nibabel 本身就是纯 Python，元数据解析不涉及性能瓶颈
core/ (数据模型) Python + C++ bridge ImageData 在 Python 侧为 numpy，但底层 buffer 由 C++ bridge 管理，确保与 VTK/ITK 共享内存
rendering/ (渲染) Python (编排) + C++ (计算) VTK 管线搭建在 Python 侧完成；自定义 Reslice / Volume 算法用 C++ 写 VTK Filter
processing/ (分割) Python (编排) + C++ (计算) ITK Pipeline 搭建在 Python 侧完成；自定义分割算法用 C++ 写 ITK Filter
geometry/ (几何) C++ 为主 + Python 绑定 OCCT / CGAL 本身是 C++；Python 侧通过 pythonocc-core + pybind11 封装调用
native/ (整个目录) C++ + CMake 所有 C++ 源码、CMakeLists.txt、pybind11 绑定定义都在这里

2.3 C++ → Python 绑定方式总览

C++ 库绑定方式产物说明

Zero-Copy Bridge pybind11 + py::buffer_info medaxis_bridge.pyd numpy ↔ vtkImageData ↔ itkImage 三者共享同一块内存，避免拷贝

9.4 Undo/Redo 命令栈

基于 Qt QUndoStack 的命令模式。所有用户可感知的状态变更（分割、编辑、测量、视图操作）都封装为 QUndoCommand 子类。

命令类型清单

命令Undo 操作Redo 操作
EditLabelCommand 恢复 LabelData.array 的旧版本（差分存储） 重新应用修改
DeleteLabelCommand 恢复 LabelData 到 LabelManager 重新删除
AddMeasurementCommand 移除测量标注 重新添加
MoveMeasurementCommand 移动回旧位置 移动到新位置
ChangeViewCommand 恢复旧视图参数 (slice/window/level/zoom/pan) 应用新视图参数
RunAlgorithmCommand 移除算法产生的 LabelData 重新执行算法（参数已记录）
CropVolumeCommand 恢复原始 VolumeData 重新裁剪

差分存储优化 (LabelData)

LabelData 可达几十 MB，全量复制不可行。采用 稀疏差分 策略： 仅存储修改区域的 bounding box + 修改前后的 voxel 差异。典型画笔涂抹操作仅需存储 ~KB 级别的差分数据。

内存管理

策略说明
最大 Undo 步数默认 200 步，可配置。超过后最早的历史被丢弃
内存上限Undo 栈总内存 ≤ 500MB，超过后自动压缩/丢弃最旧条目
内存监控状态栏显示 Undo 栈当前使用量
